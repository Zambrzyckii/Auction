# ADR-010: Shared outbox infrastructure and leased claims

- **Status:** accepted (2026-11-01) · PL: [../../pl/adr/010-shared-outbox-infrastructure.md](../../pl/adr/010-shared-outbox-infrastructure.md)
- **Context:** the outbox entity and its processor existed as eight hand-synchronized per-module copies (ADR-002), already drifting (Identity's setters), and the architecture review before phase five flagged two delivery gaps on top of the copies: the poll took no claim, so a second instance of the same module would routinely publish the same rows twice, and processed rows accumulated forever under a poll that scanned the whole table. The constraints: `Shared.Integration` stays contracts-only with no EF Core dependency, each module keeps its own outbox table (ADR-002), and PgBouncer pools transactions (ADR-007), which rules out session-scoped advisory locks for the claim.
- **Decision:** a second shared project, `AuctionServer.Shared.Infrastructure`, referencing EF Core and `Shared.Integration`, holds one `OutboxMessage` entity, `OutboxMessageModel.Configure(builder, tableName)` for the per-module table mapping, one generic `OutboxProcessor<TContext>` registered per module through `AddOutboxProcessor<TContext>(moduleName)` and `OutboxCourier` with the claim and cleanup queries. The claim is a single `UPDATE` setting `LeasedUntil = now() + 30 s` on ids picked by a subquery with `ORDER BY "CreatedOn" LIMIT 20 FOR UPDATE SKIP LOCKED` and returning the rows — one statement is one implicit transaction, so it stays correct behind transaction pooling. A partial index `IX_{table}_Pending` on `CreatedOn`, filtered to undelivered rows, serves the claim, and once an hour the processor deletes rows processed more than 7 days ago; dead rows are never deleted. The module boundary rule splits in two: `Shared.Integration` remains the only legal contact surface between modules, while `Shared.Infrastructure` is shared implementation that modules must not use to talk to each other. The inbox stays copied per module.
- **Consequences:** a change to outbox behavior lands once instead of eight times, and the courier is tested once against a real postgres in `AuctionServer.Shared.Infrastructure.Tests` (concurrent claims take disjoint rows, a leased row is not re-claimed, cleanup deletes only processed rows past retention) instead of three divergent entity-test copies. A lease expiring mid-publish lets another instance publish the row again, which at-least-once delivery and the consumer inboxes already absorb. Moving the entity's CLR name without touching the schema meant hand-editing the eight model snapshots instead of generating eight empty migrations, verified with `dotnet ef migrations has-pending-model-changes`; the `Add_Outbox_Lease` migrations add the column and the index in every module. Profiles keeps no reference to the new project, and a saga test fast-forwarding retries must now also clear `LeasedUntil`, not just `NextAttemptOn`.
