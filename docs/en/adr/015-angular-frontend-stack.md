# ADR-015: Angular 22 frontend stack

- **Status:** accepted (2026-11-08) · PL: [../../pl/adr/015-angular-frontend-stack.md](../../pl/adr/015-angular-frontend-stack.md)
- **Context:** the seven-phase server-infrastructure plan is complete and the backend offers a browser client everything it needs through the nginx gateway on `:8080`: 51 endpoints, one `{"error":"..."}` contract, CORS for `http://localhost:4200` and the candidate views recorded in [frontend.md](../frontend.md). The original design note named Angular as the framework, and nothing else was decided. The frontend is the owner's own learning stack, so the kickoff had to settle the version, the tooling, the repository layout and the client-side answers to what the backend does not provide: a push channel, a "my auctions" listing and a token that outlives its 15 minutes.
- **Decision:** the client is Angular 22 with the CLI defaults, which today mean standalone components, signals, zoneless change detection, Vitest as the test runner and SCSS, scaffolded as one application with `package.json` directly in `Frontend/`, symmetric to `Backend/`. Styling is plain SCSS: Angular Material and Tailwind were rejected because the MVP UI is deliberately bare, only readable enough for manual testing, and the real UI/UX pass is a separate branch of the plan at the very end of the project, after the frontend logic, the backend fixes and the AI bots; npm packages beyond the `ng new` scaffold need the owner's separate consent. Forms use Signal Forms, stable since v22 and consistent with the signal-based rest of the application, with a fallback to Reactive Forms only by separate consent. The dev server reaches the API through a proxy to `http://localhost:8080` rather than CORS, mirroring the target layout where nginx one day serves the SPA from the same origin. The client polls instead of listening: the auction detail every 2-3 s, matching the 2 s TTL of the Auctions read cache (ADR-009), the list less often, and every asynchronous outcome (wallet creation, auction activation, bid confirmation) is rendered as an explicit waiting state rather than assumed immediate. The 15-minute player token is handled by re-login, the HTTP interceptor clears the token on a 401 and redirects to the login view with a returnUrl; a refresh flow stays tracked as issue #18, because the future OIDC provider named in [infrastructure.md](../infrastructure.md) would bring one anyway. The "my auctions" endpoint stays deferred until after the MVP, so the first batches change nothing in the backend.
- **Consequences:** the whole MVP builds on the existing API, so the backend suite is untouched and frontend batches are verified by `ng build`, Vitest and manual runs against the compose stack. CI gains a `frontend` job, and the two pieces of CI noise the kickoff review surfaced, the gateway test running a different nginx version than compose and the api image pushed to GHCR on frontend-only commits, are accepted for now and tracked as issues #19 and #20. A player can still be logged out mid-action when the token expires, an accepted cost until the refresh flow lands. Polling spends requests instead of connections and stays far under the gateway's per-IP limits at the chosen intervals. The visual debt is deliberate: views stay plain HTML with a minimal stylesheet until the UI/UX branch, so nothing in these batches is designed to be looked at, only to be used. The toolchain now includes Node 26 and the Vitest runner in jsdom, and Dependabot watches `/Frontend` npm packages with Angular majors excluded, because those migrate through `ng update`.
