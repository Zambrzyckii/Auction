# ADR-009: TTL read cache behind a module-owned seam, HybridCache with Redis L2

- **Status:** accepted (2026-11-01) · PL: [../../pl/adr/009-hybrid-read-cache-in-auctions.md](../../pl/adr/009-hybrid-read-cache-in-auctions.md)
- **Context:** phase four of the server-infrastructure plan adds a cache for the three anonymous Auctions reads (list, detail, bid history), the queries `browse.js` hammers and the only hot read path today. The module rules forbid other modules from seeing the cache, and the owner's consistency budget allows short staleness on anonymous reads (the outbox already delays bid visibility by 3-9 s) but none on writes. `OutputCache` was rejected because it skips requests with an `Authorization` header by default and the planned Angular client sends a JWT everywhere, so a policy ignoring auth would become a per-caller data leak. An nginx microcache was noted as an alternative and not combined with this one, because two layers would multiply the staleness windows. Candidate libraries: hand-rolled `IMemoryCache` plus `IDistributedCache`, FusionCache, or the platform's `HybridCache`.
- **Decision:** the cache is TTL-only cache-aside and lives behind the module-owned `IAuctionReadCache` seam. Query records implement `ICachedQuery` (key `auctions:{kind}:v1:{arg}` and a TTL picked from `Auctions:ReadCache`, default 2 s, validated 1-60 s), a MediatR open behavior intercepts them, and `HybridAuctionReadCache` wraps `HybridCache` with `Expiration == LocalCacheExpiration`, fail-open (log, count on the `AuctionServer.Auctions.Cache` meter, fall back to the database; factory exceptions propagate uncached, so not-found is never stored) and no invalidation on write. The host's fail-fast `Cache` section picks the state: off resolves the seam to a pass-through, on registers `AddHybridCache()` (L1), and a configured `Cache:Redis:ConnectionString` adds Redis as L2 through `AddStackExchangeRedisCache` with `AbortOnConnectFail=false` and 500/300 ms timeouts, instance prefix `auctionserver:`. Compose runs `redis:7.2-alpine` capped at 64 MB with `allkeys-lru` and no persistence, and the api does not depend on it.
- **Consequences:** anonymous reads may be up to 2 s behind the database on top of the outbox lag, which moved the measured `visibility_lag` p95 from 6.02 s to 7.29 s and the k6 threshold to 8 s, the owner's call recorded in [performance.md](../performance.md); writes and sagas never read the cache, and a dead Redis costs latency, not correctness, proven by an integration test that stops the container mid-run. At one instance L2 is nearly idle (12 keyspace hits against 762 misses) because both layers expire together, so Redis is wiring proven ahead of the second instance, not a present win; the measured benefit today is the 92.6% hit ratio that keeps about thirteen out of fourteen reads away from postgres. HybridCache has no invalidation backplane, so a future multi-instance deployment with explicit invalidation would need `LocalCacheExpiration` shortened or a pub/sub layer, and the `v1` key segment is the schema-change escape hatch. Swapping the library away from HybridCache touches one wrapper file, not the queries.
