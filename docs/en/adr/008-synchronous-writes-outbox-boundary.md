# ADR-008: The outbox is the asynchrony boundary, HTTP writes answer synchronously

- **Status:** accepted (2026-10-31) · PL: [../../pl/adr/008-synchronous-writes-outbox-boundary.md](../../pl/adr/008-synchronous-writes-outbox-boundary.md)
- **Context:** during the 2026-10-24 architecture review the owner raised queueing every mutating HTTP request (save, add, delete) through the broker, with reads staying synchronous, for players and bots alike. The target documents give RabbitMQ two narrower roles. It is the transport for integration events behind `IIntegrationEventPublisher` ([ADR-003](003-in-process-event-bus-before-rabbitmq.md)) and a consume-only queue of market events for the planned bots ([bots.md](../bots.md)). Gameplay endpoints answer with the domain result in the same response. A bid returns 201 or 409 at once, a roulette spin and a blackjack action return the game state, and the k6 bidding scenario reads the current price right before posting a bid. The SPA has no push channel to deliver a deferred result and the gateway strips the `Connection` header, which blocks WebSocket. `visibility_lag` p95 already sits at its 6 s threshold ([performance.md](../performance.md)). Most request/reply sagas match replies without a request id (only the pawnshop payment and the casino chip purchase carry one), so a queued, retried command could not be correlated safely today.
- **Decision:** the transactional outbox stays the only asynchrony boundary. A mutating endpoint performs one local transaction (the state change plus its outbox rows) and answers synchronously with the domain result. Cross-module effects remain asynchronous through the outbox, and phase 5 changes only how those stored rows travel between modules. Client-facing writes are not queued, for players or for bots. An endpoint may answer 202 Accepted and complete through events only as an explicit, documented exception when the caller does not need the result, as the casino cash-out already does. Protection against write spikes belongs to PgBouncer, the gateway IP limits and the phase-7 per-user rate limiter, not to a command queue.
- **Consequences:** bidding and the casino games keep their immediate feedback and the SPA needs no push channel for ordinary writes. The bid path is not charged an extra broker hop against the already breached latency budget. Any future 202-style endpoint is a conscious per-endpoint decision and must carry its own request id and completion signal. If queued commands are ever needed at scale, the missing prerequisite is a request id on every request/reply pair. The pending-bid finding from the 2026-10-24 review was fixed exactly this way on 2026-10-25 (a request id on the pending bid, replies matched against it and a timeout), and the entry-fee finding in Warehouses still waits on the same prerequisite.
